# 보물 여행 결제 키트 (코스 도전권 4,000원 / 9,900원 · 추첨 1인 1회·무료 응모 · 적립금 조정)

회원이 결제하면 코스에 도전할 수 있게 하는 키트입니다. 결제는 **KG이니시스** 결제창(PC 웹표준 · 모바일)을 씁니다. 토스페이는 뺐습니다.

완주 보상 추첨은 **시즌마다 한 사람당 1회**만 응모되게 했고, **결제하지 않아도 첫 보물 무료 체험 뒤 무료로 응모**할 수 있습니다. 시즌 1 상금은 **1·2·3등 150·100·50만 원**입니다. 전체 코스 패스로 여러 코스를 완주해도 당첨 기회는 늘지 않습니다. 상금은 도전권 가격과 따로, 마케팅 예산(`server/src/data/draw.json`)으로 관리합니다.

## 무엇이 바뀌나요

| 화면 / 서버 | 바뀌는 점 |
|---|---|
| `client/public/pay.html` (새 파일) | 결제 페이지. 1 상품 정보 → 2 결제 금액 → 3 결제 수단 → 4 약관 동의 및 결제 진행 |
| `client/public/ar/course.html` | 첫 보물 1곳은 무료 체험. 그다음 보물을 열 때 도전권을 확인하고, 없으면 로그인 또는 구매 안내 창을 띄움 |
| `client/public/bomul.html` | 코스 상세의 「AR 탁본 시작하기」 옆에 「도전권 구매 · 4,000원부터」 버튼 (결제가 켜졌을 때만 보임) |
| `server` | `/api/pay/*` API, 주문(PayOrder)·도전권(CourseTicket) 모델, 이니시스 승인(PC·모바일)·망취소·INIAPI 취소, 관리자 결제 목록·취소 |
| `server` 추첨 | `/api/draw/*` API, 응모(DrawEntry, 시즌+회원 고유), 관리자 예산 요약·공정 추첨 |
| AR 보물 상자 | 상자를 열면 서버에 추첨 응모. 이미 응모했으면 「이미 「○○」 완주로 응모되어 있어요」 |
| 추첨 설명 문구 | 「자동으로 응모되었어요」 → 「시즌마다 한 사람당 한 번이라, 여러 코스를 완주해도 당첨 기회는 같아요」 (영어·중국어 번역 포함) |
| 상품 정보 | 「궁·유적지 입장료는 별도예요」 안내 |
| 결제 페이지·메인 | 결제 금액 아래와 메인 유의사항(새 디자인)에 1인 1회·무료 응모 안내, 메인 상금 표시 150·100·50만 원 |
| AR 무료 응모 | 첫 보물 탁본 직후와 「도전권이 필요해요」 창에 「추첨에 무료 응모하기」 버튼 |
| 적립금 | 완주 100,000P → **500P**, 현장 모드로 모든 보물을 탁본한 코스만 적립(데모 모드 0P). 이 기기에 쌓인 예전 포인트는 1/200 로 바뀜 |
| 교환표 | 1P ≈ 1원. 1천 원(1,000P) · 3천 원(3,000P) · 스타벅스(5,000P) · 문화상품권 1만 원(10,000P) · 외식 1만 5천 원(15,000P) |
| 메인·상세 문구 | 「적립금 100,000P」 → 「500P · 현장 완주」 (영어·중국어 상세 번역 포함) |

**안전장치:** `PAYMENTS_MODE` 의 기본값이 `off` 입니다. 키트를 설치만 하면 사이트는 지금처럼 모두 무료로 동작합니다. 켜기 전에 충분히 시험할 수 있습니다.

## 순서 (20~30분)

1. 저장소 맨 위에 `_pay_kit` 폴더를 놓습니다.
2. 아래 명령을 실행합니다. Cursor 에게 맡겨도 됩니다(CURSOR-PROMPTS-pay.md 의 P-0).
   ```
   node _pay_kit/install.mjs --dry
   node _pay_kit/install.mjs
   node _pay_kit/check.mjs
   node tools/i18n/build.cjs      # 다국어 키트를 설치했다면
   ```
3. `CURSOR-PROMPTS-pay.md` 를 열고 P-1 부터 차례로 Cursor 채팅에 붙여 넣습니다.
4. 로컬에서 `PAYMENTS_MODE=mock` 으로 전체 흐름을 시험합니다.
5. `PAYMENTS_MODE=inicis` 로 바꾸면 키 없이도 이니시스 **공개 테스트 상점**(INIpayTest)으로 실제 결제창을 시험할 수 있습니다. 돈은 나가지 않습니다.
6. 이니시스 계약이 끝나면 `INICIS_ENV=prod`, `INICIS_MID`, `INICIS_SIGNKEY`, `INICIS_API_KEY` 를 Heroku 환경변수에 넣고 배포합니다.

## 디자인 키트·다국어 키트와 함께 쓸 때

- 순서는 상관없습니다. `tools/pay/patch.mjs` 는 원래 화면이든 새 디자인 화면이든 같은 자리(「AR 탁본 시작하기」 버튼)를 찾아 넣습니다.
- 다만 **디자인 키트를 나중에 적용하면** 디자인 키트가 `bomul.html` 을 새 파일로 바꿀 수 있습니다. 그때는 `node tools/pay/patch.mjs` 를 한 번 더 실행하세요. 여러 번 실행해도 한 번만 들어갑니다.
- 결제 페이지는 한국어로만 만들었습니다. 원화 결제라서입니다.

## 운영 전에 꼭 정할 것 (지금은 임시값)

- **KG이니시스 계약:** 상점아이디(MID), 웹결제 Sign Key, INIAPI Key, INIAPI 요청 서버 IP 등록, 카카오페이·네이버페이 「간편결제 직접호출」 설정. 자세한 내용은 SPEC-PAY.md 11장.

- **추첨 일정·예산:** `server/src/data/draw.json`
  - 응모 마감 2027-02-28, 추첨 2027-03-05 는 예시입니다.
  - 상금 300만 원(150·100·50만 원)에 회사가 세금 22%를 대신 내면 실제 비용은 3,846,154원입니다. 예산은 385만 원으로 잡았습니다.
  - 메인 배너 사진에는 상금 숫자가 없어 바꿀 필요가 없습니다. 다른 홍보물(SNS·포스터)에 300만 원이 적혀 있다면 함께 바꾸세요.
  - 관리자 요약(`GET /api/draw/summary`)에서 결제 매출 대비 상금 비율과 예산 초과 여부를 볼 수 있습니다.
- **적립금·교환표 (조정함):**
  - 완주 1코스 = 500P 로, 1코스 도전권 4,000원의 12.5% 입니다. 9,900원 패스로 30일에 3코스를 돌면 1,500P(약 15%) 입니다.
  - 적립은 코스마다 한 번입니다. 한 사람이 받을 수 있는 최대치는 37코스 × 500P = 18,500P 입니다.
  - 데모 모드(현장 밖) 완주는 적립금이 없습니다. 집에서 전 코스를 완주해 포인트를 모으는 것을 막기 위해서입니다.
  - 포인트는 아직 휴대폰(이 기기)에만 저장돼 바꿔칠 수 있습니다. 실제 교환을 시작하기 전에 서버 지갑(SPEC-COMPLETION 의 ArWallet)과 서버 완주 인증을 붙이세요.
  - 관리자 「AR 상품 설정」에 예전 값을 저장해 두었다면 그 값이 우선입니다. 거기서도 바꾸세요.
- **상품 이름·기간:** 「1코스 도전권 4,000원 · 30일」, 「전체 코스 패스 9,900원 · 30일」. 바꾸려면 `server/src/data/payProducts.json` 만 고치면 됩니다.
- **무료 체험:** 첫 보물 1곳(`freeTrialStops`). 취소·환불 규정 제2조 제3항(구매 전 무료 체험 제공)에 맞추려고 넣었습니다. 0 으로 두면 처음부터 도전권이 필요합니다.
- **약관·환불 문구:** pay.html 의 약관 요약과 환불 안내는 지금 `refund.html` 을 바탕으로 쓴 초안입니다. 운영 전에 법률 검토를 받으세요.
- **refund.html 고칠 점:**
  - 시행일이 「2027년 11월 11일」로 적혀 있습니다.
  - 제3조 「묶음 상품 중 일부 코스만 시작함 → 시작하지 않은 코스의 정가 합계」를 전체 코스 패스(9,900원)에 그대로 쓰면, 환불액이 결제액보다 커집니다. 예를 들어 36코스 × 4,000원입니다. 「결제 금액 안에서」 같은 상한을 넣어야 합니다. 결제 페이지에는 「결제 금액 안에서」로 적어 두었습니다.

자세한 설계는 `SPEC-PAY.md` 에 있습니다.
